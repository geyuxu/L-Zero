L-Zero: The AI-Native Deterministic ISA
Bridging Probabilistic Intent and Deterministic Execution
(连接概率性意图与确定性执行的桥梁)
Version: 0.1.0 (Research Preview)
Author: Yuxu Ge (MSc Candidate, University of York)
Repository: github.com/yuxu-ge/l-zero
Abstract (摘要)
Current Autonomous Agent architectures rely heavily on generating and executing Python code. While flexible, this approach introduces significant risks regarding safety (arbitrary code execution), indeterminism (environment dependency), and opacity (black-box logic).
L-Zero proposes a novel Instruction Set Architecture (ISA) designed explicitly for Large Language Models (LLMs). Unlike human-centric languages, L-Zero provides a Semantic Firewall that forces probabilistic AI intent to collapse into a verifiable, deterministic state before execution. Built on a lightweight, Rust-based Virtual Machine without Garbage Collection, L-Zero transforms agent actions into Replayable Cognitive Traces, enabling precise auditing, formal verification, and "Gas as Cognitive Cost" research.
1. The Crisis of "Prompt-to-Python" (背景与挑战)
The dominant paradigm for Agents today is Prompt -> Python Code -> Subprocess. This architecture faces three critical failures:
 * The Safety Failure: Giving an LLM access to a Python interpreter is equivalent to granting root access. Sandboxing Docker containers is resource-heavy and complex to secure against ReDoS (Regular Expression Denial of Service) or infinite loops.
 * The Deterministic Failure: Python scripts behavior varies based on libraries, versions, and OS environments. An agent that works today may fail tomorrow due to a minor dependency change.
 * The Auditability Failure: When an agent fails, we often only see the final error. We lack a granular, instruction-level trace of the reasoning steps that led to the action.
Thesis: We need a computing substrate designed for machines to write, not humans.
2. Core Philosophy: Three Research Pillars (核心哲学)
L-Zero is not just a Virtual Machine; it is a research instrument built on three pillars:
2.1 The Semantic Firewall (语义防火墙)
L-Zero acts as a strict boundary between the "Dream" (LLM Hallucination) and the "Reality" (System Execution).
 * Constraint: The LLM must translate its fuzzy intent into a rigid, 28-instruction JSON format.
 * Validation: Invalid syntax or dangerous logic (e.g., unauthorized memory access) is rejected by the VM before runtime, protecting the host system.
2.2 Replayable Cognitive Traces (可回放的认知轨迹)
In L-Zero, execution is 100% deterministic.
 * Every instruction, memory change, and branch decision is recorded.
 * This turns an Agent's execution into a Cognitive Trace—a verifiable log that allows researchers to replay an agent's "thought process" on any device, ensuring that a bug found in production can be perfectly reproduced in the lab.
2.3 Gas as Cognitive Cost (Gas 即认知成本)
L-Zero introduces Gas Metering not just for resource capping, but as a metric for Efficiency.
 * We hypothesize that "Gas Used" is a better proxy for "Reasoning Effort" than Token Count.
 * This enables future research into Reward Shaping: training models to achieve goals with the minimum "Cognitive Gas."
3. System Architecture (系统架构)
L-Zero is built to be "Write Once, Run Everywhere" — from Cloud Servers to Edge Devices (iOS/IoT).
 * Host Layer (Rust): Handles memory safety, borrow checking, and system call dispatching. Zero Garbage Collection ensuring predictable latency.
 * VM Layer (WASM): Compiled to WebAssembly, allowing the runtime to be <300KB and embeddable in browsers or mobile apps.
 * Guest Layer (JSON ISA): The bytecode format generated by the LLM.

4. The L-Zero ISA (指令集架构)
The ISA is a Frozen Core of 28 atomic instructions, designed to be Turing-Complete yet minimal enough for LLMs to master without syntax errors.
| Group | Instructions | Description |
|---|---|---|
| System | HALT, PANIC, GAS, DUMP | Lifecycle and Debugging. |
| State | SET, MOV, SWAP | Register manipulation (R0-R255). |
| Math | ADD, SUB, MUL, DIV, MOD | Integer arithmetic (No floating point non-determinism). |
| Logic | AND, OR, XOR, NOT | Bitwise operations. |
| Control | CMP, JMP, BEQ, BGT, BLT | Branching (The basis of logic). |
| Memory | NEW, FREE, READ, WRITE | Heap management (String/Vector). |
| AI-Native | REGEX, TEXEC | The Core Innovation. |
 * REGEX: Built-in linear-time regex engine for parsing unstructured text (logs, HTML).
 * TEXEC (Tool Execution): A universal syscall interface. Instead of adding new opcodes (e.g., HTTP_GET), L-Zero uses TEXEC tool_id to invoke host capabilities safely.
5. Preliminary Hypotheses & Experiments (实验假设)
This project aims to validate the following research hypotheses:
H1: Syntactic Robustness
> LLMs generate valid L-Zero JSON bytecode with a higher success rate than valid Python code for complex algorithmic tasks, due to the constrained search space of the ISA.
> 
H2: Execution Safety
> The L-Zero Sandbox prevents 100% of "Resource Exhaustion Attacks" (e.g., infinite loops, memory bombs) that typically crash Python interpreters in Agent scenarios.
> 
H3: Traceability
> L-Zero execution traces provide significantly higher "Explainability" scores for Agent failures compared to Python stack traces.
> 
(Benchmarks and comparison scripts are located in the benchmarks/ directory).
